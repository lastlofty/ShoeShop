# Паспорт проекта

## 1. Название проекта

**ShoeShop — информационная система магазина обуви «Топотун»**: настольное приложение (C#, WPF) и база данных MySQL для учёта товаров, остатков и заказов с выдачей через пункты выдачи.

## 2. Проблема

Магазин «Топотун» ведёт товары, пользователей и заказы в четырёх разрозненных Excel-файлах: в них повторяются названия, адрес пункта выдачи записан одной строкой, в датах встречаются ошибки (например, 30.02.2025). Менеджер не видит актуальный остаток, а покупатель не может сам посмотреть каталог, поэтому продавец тратит время на ручные сверки.

## 3. Пользователи

- **Гость** — просматривает каталог без входа в систему.
- **Авторизованный клиент** — входит по логину и паролю, просматривает каталог, оформляет заказы.
- **Менеджер** — ищет, фильтрует и сортирует товары, просматривает заказы.
- **Администратор** — добавляет, редактирует и удаляет товары и заказы, меняет фото товара.
- **Оператор загрузки** — один раз переносит данные заказчика из файлов import в БД.

## 4. Цель проекта

Дать сотрудникам магазина и покупателям одну систему, где каталог, остатки и заказы берутся из единой базы данных и всегда актуальны.

## 5. Метрики успеха

| Метрика | Целевое значение | Как замерить |
|---|---|---|
| Время оформления заказа клиентом | < 2 минут | секундомер на сценарии BPMN «Оформление заказа» |
| Поиск товара менеджером | ≤ 3 действия, результат < 1 с | поиск/фильтр/сортировка без кнопки «Найти» |
| Полнота импорта данных ДЭ | 100 % строк (30 / 10 / 10 / 36) | `db/checks.sql`, запрос 1 |
| Ошибки ссылочной целостности | 0 | попытка вставить «битый» FK отклоняется СУБД |
| Аварийные завершения при отладке | 0 на всех 11 сценариях | файл скриншотов отладки |

## 6. Границы (что НЕ делаем)

- Не подключаем реальную онлайн-оплату: оплата в учебном проекте — симулятор (занятие 10).
- Нет мобильного приложения и сайта — только настольное приложение Windows.
- Курьерская доставка не моделируется: заказ выдаётся в одном из 36 пунктов выдачи.
- Нет интеграции с 1С и складским учётом поставщиков.

## 7. Риски

| Риск | Что делаем |
|---|---|
| Ошибки в исходных данных (пустые строки, 30.02, адрес без запятой) | Исходники не трогаем, все исправления — только в CSV, каждое описано в `db/README.md` |
| Кракозябры при импорте CSV | Сохраняем CSV в UTF-8, при сбое пересохраняем в ANSI (памятка пары 10) |
| Не успеваем к контрольной точке | Приоритет: БД и каталог → вход по ролям → CRUD; Гантт обновляем каждую пару |
| Потеря БД на учебном ПК | Скрипты `create_v1.sql` + `data.sql` и резервная копия в `db/backup/` |
